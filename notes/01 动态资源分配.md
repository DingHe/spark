# 步骤一：开启外部shuffle Service(关键前提)

动态分配要求执行器能够安全地退出，而不会丢失 Shuffle 中间数据。
因此，必须启用一个独立于执行器进程的 外部 Shuffle Service。

## YARN 环境配置示例（通常由集群管理员完成）

1. 修改 yarn-site.xml

yarn.nodemanager.aux-services=spark_shuffle

yarn.nodemanager.aux-services.spark_shuffle.class=org.apache.spark.network.yarn.YarnShuffleService

其他参数可以通过spark-shuffle-site.xml文件配置

2. 在 Spark 配置中启用 Shuffle Service

spark.shuffle.service.enabled 为 true


# 步骤二：配置Spark应用程序参数

无论在哪种集群管理器（YARN、Mesos 或 Standalone）上运行，
都需要在 Spark 配置文件 (spark-defaults.conf) 或提交任务时设置以下核心参数：

| 配置项                                                       |              值              |                                                            作用 |
|:----------------------------------------------------------|:---------------------------:|--------------------------------------------------------------:|
| spark.shuffle.service.enabled	                            |            true             |                    必须启用。 确保 Spark Shuffle 数据由外部服务处理，允许执行器安全退出 |
| spark.dynamicAllocation.enabled	                          |            true             |                                  核心开关。 启用 Spark 应用程序的动态资源分配功能 |
| spark.dynamicAllocation.minExecutors	                     |          (例如: 1)	           |                        应用程序应始终保持的最小执行器数量。Spark 不会删除低于此数量的执行器。 |
| spark.dynamicAllocation.maxExecutors	                     |          (例如: 30)	          |                                  应用程序可以请求的最大执行器数量。这是资源分配的硬上限。 |
| spark.dynamicAllocation.initialExecutors	                 | (例如: 1 或与 minExecutors 相同)	 |                                            应用程序启动时最初请求的执行器数量。 |
| spark.dynamicAllocation.executorIdleTimeout	              |            60s	             |                               当执行器空闲时间超过此阈值时，Spark 会将其删除并释放资源 |
| spark.dynamicAllocation.schedulerBacklogTimeout	          |             1s              |                       如果积压的待处理任务队列持续超过此时间，Spark 会触发一次新的执行器请求。 |
| spark.dynamicAllocation.sustainedSchedulerBacklogTimeout	 |             5s              | 如果在 schedulerBacklogTimeout 后任务积压仍然存在，Spark 会以指数级增长的速率再次触发请求。 |


# 如何配置（spark-submit）示例

```bash
spark-submit \
--master yarn \
--conf spark.dynamicAllocation.enabled=true \
--conf spark.shuffle.service.enabled=true \
--conf spark.dynamicAllocation.minExecutors=1 \
--conf spark.dynamicAllocation.maxExecutors=50 \
--conf spark.dynamicAllocation.initialExecutors=5 \
--class com.example.YourApp \
your_app.jar
```
